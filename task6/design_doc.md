## Дизайн-документ: расширение pg_array_utils

-------
#### *Примечание: документ является черновиком и может дополняться*
-------

### Цель:
Разработать расширение `pg_array_utils` для PostgreSQL на языке C с набором IMMUTABLE-функций, реализующих преобразование и манипуляции с массивами.

### Общие решения и предположения:
- Все SQL-функции объявляются `STRICT` и `IMMUTABLE`; NULL-аргументы в C-код не попадают.
- Типы `anyarray`/`anyelement` проверяются PostgreSQL на уровне SQL; C-код дополнительно проверяет типы там, где это важно для логики.
- Размеры и индексы передаются как `int32`; для больших результатов, где это явно сделано, проверяется `MaxAllocSize`.
- Для многомерных массивов используется порядок хранения PostgreSQL (row-major).
- Поведение lower bounds (`lbs`) различается по функциям и описано ниже.
- Обработка NULL также различается по функциям и описана ниже.

### Разрабатываемые функции:

#### **1. array_flatten**

- **Назначение:** Преобразование многомерного массива в одномерный (в порядке хранения).
- **Прототип:** `array_flatten ( anyarray ) → anyarray`
- **Сигнатура (SQL):** `FUNCTION array_flatten(anyarray) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Вход/выход:**
    - Вход: `anyarray`;
    - Выход: `anyarray`; для массива с `ARR_NDIM <= 1` или пустого массива возвращается исходный массив без изменений;
    - Для многомерного непустого массива результат — одномерный массив с `lbs = 1`; элементы и NULL-элементы сохраняются, тип элемента сохраняется.
- **Используемый алгоритм/решение:**
    Для многомерного непустого массива используется `deconstruct_array`, затем `construct_array` для сборки одномерного массива. Для 1D/пустого массива — ранний возврат аргумента.
- **Ограничения:**
    - Для многомерного массива lower bound результата сбрасывается в 1;
    - Для 1D и пустого массива возвращается исходный массив, поэтому его lower bound сохраняется.
- **Предполагаемые тесты:**
    - Обычный случай — несколько тестов (разные типы элементов массива);
    - Одномерный массив — возврат ввода;
    - Пустой массив — возврат ввода;
    - Большой массив;
    - N-мерный массив — штатно, результат 1D с `lbs = 1`;
    - Ошибка ввода (аргумент — не массив).

#### **2. array_chunk**

- **Назначение:** Разбиение непустого одномерного массива на двумерный массив чанков заданного размера. Каждый чанк имеет длину `size`; если элементов не хватает, чанк дополняется NULL-элементами.
- **Прототип:** `array_chunk ( anyarray, size integer ) → anyarray`
- **Сигнатура (SQL):** `FUNCTION array_chunk(anyarray, size integer) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Вход/выход:**
    - Вход: непустой одномерный `anyarray`, `size integer`;
    - Выход: двумерный `anyarray` с размерностями `dims = {(n + size - 1) / size, size}` и нижними границами `lbs = {1, 1}`, где `n` — число элементов входа;
    - Тип элементов сохраняется; NULL-элементы входа сохраняются; недостающие элементы заполняются NULL.
- **Используемый алгоритм/решение:**
    `deconstruct_array` => расчёт `chunks_cnt = (n + size - 1) / size;` и `new_size = chunks_cnt * size` => расширение массивов `elements`/`nulls` => заполнение хвоста `NULL` => сборка с помощью `construct_md_array`.
- **Ограничения:**
    - Входной массив должен быть непустым и одномерным;
    - `size` должен быть положительным;
    - `size > n` не является ошибкой: получается один чанк, дополненный NULL.
- **Предполагаемые тесты:**
    - Обычный случай — несколько тестов:
        - Разные типы элементов массива;
        - Разные положительные значения `size`;
        - `size > n` — один чанк с NULL-дополнением;
    - N-мерный массив — ошибка;
    - Пустой массив — ошибка;
    - Большой массив;
    - Ошибка ввода:
        - 1 аргумент — не массив;
        - `size` — не int;
        - `size <= 0`;
    - Массив с NULL-элементами — штатно.

#### **3. array_zip**

- **Назначение:** Формирование массива `jsonb`, каждый элемент которого — JSON-объект с полями `"f1"`, `"f2"`, ... по одному значению из каждого входного массива. 
- **Прототип:** `array_zip ( anyarray, anyarray [, ...] ) → anyarray`
- **Сигнатура (SQL):** `FUNCTION array_zip(VARIADIC anyarray) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Вход/выход:**
    - Вход: один или несколько `anyarray`;
    - Выход: `jsonb[]`, длина равна максимальному значению `dims[0]` среди непустых входов; `lbs = {1}`;
    - Каждый элемент результата — JSON-объект вида `{"f1": ..., "f2": ..., ... , "fN": ...}`, где `N` - количество входных массивов;
    - Для 1D-массива значение i-го поля — i-й элемент или `NULL`, если `i >= длине этого массива` или он NULL;
    - Для N-мерного массива (`N > 1`) значение i-го поля — JSON-представление подмассива по оставшимся размерностям `dims[1..]` (i-й "строки" первого измерения), сериализуемое через `pgau_array_to_StringInfo` или `NULL`, если `i >= dims[0]`;
    - Если все входные массивы пустые — возвращается пустой `jsonb[]`.
- **Используемый алгоритм/решение:**
    Для каждого входного массива: `deconstruct_array`, определение `dims[0]`, числа элементов на одну "строку" первого измерения и признака пустоты. Затем для `i = 0 .. max_len - 1` строится JSON-строка через `StringInfo`, поля `"f<j>"`, и преобразуется в `jsonb` через `DirectFunctionCall1(jsonb_in, ...)`. Результат собирается `construct_md_array`.
- **Ограничения:**
    - Нулевое число аргументов — ошибка;
    - Lower bounds входных массивов игнорируются; используется только `dims[0]`;
    - Числовые и boolean-значения выводятся в исходном виде; остальные — как JSON-строки.
- **Предполагаемые тесты:**
    - Обычный случай — несколько тестов (разное количество входных массивов);
    - Большое количество массивов;
    - Большие размеры массивов;
    - Ошибка ввода (ни одного входного массива);
    - Один или несколько массивов пустые — штатно, соответствующие поля - `NULL`;
    - Все массивы пустые — пустой `jsonb[]`;
    - Один или несколько массивов состоят из NULL — штатно;
    - Один или несколько N-мерных массивов — штатно.

#### **4. array_compact**

- **Назначение:** Удаление «пустых» элементов. Режимы:
    - `'null'` — удалить NULL;
    - `'zero'` — удалить числовые нули (0);
    - `'empty'` — удалить пустые строки/bytea и т.п. ("");
    - `'falsy'` — удалить NULL, false, 0, "".
- **Прототип:** `array_compact ( anyarray, mode text DEFAULT 'null' ) → anyarray`
- **Сигнатура (SQL):** `FUNCTION array_compact(anyarray, mode text DEFAULT 'null') RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Вход/выход:**
    - Вход: `anyarray`, `mode text` (сравнение точное, без приведения регистра);
    - Сначала проверяется существование режима и соответствие режима типу элементов;
    - Пустой массив возвращается как есть после проверки режима и типа;
    - Непустой массив должен быть одномерным;
    - Выход для непустого входа — одномерный массив с `lbs = 1`; если после фильтрации элементов не осталось — пустой массив;
    - `'zero'` и `'empty'` сохраняют NULL-элементы; `'null'` и `'falsy'` удаляют NULL.
- **Используемый алгоритм/решение:**
    `deconstruct_array` => проход по `elements`/`nulls` => заполнение `res_elems` (и при необходимости `res_nulls`) => `construct_array` для режимов `'null'` и `'falsy'` или `construct_md_array` для `'zero'` и `'empty'`.
    Для `'zero'` используется `pgau_numeric_is_zero`, для `'empty'` — `pgau_text_is_empty`, для `'falsy'` — фильтрация NULL, проверка истинности элемента или соответствующая функция сравнения, в зависимости от типа элементов массива.
- **Ограничения:**
    - Режим чувствителен к регистру и должен быть одним из перечня: `'null'`, `'falsy'`, `'zero'`, `'empty'`;
    - `'zero'` допустим только для числовых типов (`INT2/4/8`, `FLOAT4/8`, `NUMERIC`, `OID`, `MONEY`);
    - `'empty'` допустим только для текстовых/бинарных типов (`TEXT`, `VARCHAR`, `BPCHAR`, `CHAR`, `NAME`, `BYTEA`);
    - `'falsy'` допустим для любых типов; для типов, не являющимися `BOOLOID`, числовыми или текстовыми, происходит только фильтрация NULL элементов (аналогично `'null'`);
    - Непустой N-мерный массив — ошибка; пустой N-мерный массив возвращается без изменений.
- **Предполагаемые тесты:**
    - Обычный случай — несколько тестов:
        - Массив строк + `'empty'`;
        - Массив чисел + `'zero'`;
        - Массив строк + `'null'` и `'falsy'`;
        - Массив чисел + `'null'` и `'falsy'`;
        - Массив boolean + `'falsy'`;
    - Непустой N-мерный массив — ошибка;
    - Несоответствие режима работы входному массиву — ошибка:
        - `'zero'` не для массива чисел;
        - `'empty'` не для массива строк;
        - `'falsy'` не для массива boolean/чисел/строк;
    - Пустой массив — возврат ввода после проверки режима/типа;
    - Массив с NULL-элементами — штатно, с учётом режима;
    - Большой массив;
    - Ошибка ввода:
        - 1 аргумент — не массив;
        - mode — не строка;
        - mode — не существующий режим.

#### **5. array_pad**

*Примечание: реализованы две C-функции, регистрируемые под одним SQL-именем `array_pad` для перегрузки.*

- **Назначение:** Дополнение массива до указанной длины. Положительный `size` — дополнение в конец, отрицательный — в начало.
- **Прототипы:**
    1. `array_pad ( anyarray, size integer, value anyelement ) → anyarray`
    2. `array_pad_arr ( anyarray, size integer, value anyarray ) → anyarray`
- **Сигнатуры (SQL):**
    1. `FUNCTION array_pad(anyarray, size integer, value anyelement) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
    2. `FUNCTION array_pad(anyarray, size integer, value anyarray) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Предполагаемые тесты:**
    - Обычный случай — несколько тестов:
        - Разные типы элементов массива;
        - Разные значения `size`;
        - `size == длине массива`;
        - `size > длины массива` — дополнение;
    - Пустой оригинальный массив — штатно;
    - `value` — пустой массив — ошибка;
    - `size = 0`: с непустым исходным — ошибка, с пустым — пустой массив;
    - Ошибка ввода:
        - 1 аргумент — не массив;
        - `size` — не int;
        - `|size| < длины массива`;
        - `|size| > MaxAllocSize / sizeof(Datum)`;
        - тип `value` не соответствует типу массива;
    - Большой массив;
    - N-мерный массив — штатно для `array_pad_arr` при согласованной форме;
    - Массив с NULL-элементами — штатно.

##### 5.1. `array_pad(anyarray, integer, anyelement)`

- **Вход/выход:**
    - Вход: массив 0D/1D, `size integer`, `value anyelement`;
    - Тип `value` должен совпадать с типом элемента массива;
    - `длина исходного массива <= |size| <= MaxAllocSize / sizeof(Datum)`;
    - Выход: одномерный массив длины `|size|`;
    - Для непустого исходного массива lower bound результата равен lower bound исходного массива; для пустого — 1;
    - NULL-элементы исходного массива сохраняются; добавляемые элементы не NULL.
- **Алгоритм:** `deconstruct_array` => `memcpy` исходных элементов/NULL-карты в нужную позицию => заполнение добавки значением `value` => `construct_md_array`.
- **Ограничения:** 
    - Исходный массив должен быть 0D/1D; 
    - Тип `value` должен совпадать с типом элемента массива
    - `value` не NULL (функция STRICT).

##### 5.2. `array_pad_arr(anyarray, integer, anyarray)`

- **Вход/выход:**
    - Вход: исходный `anyarray`, `size integer`, добавляемый `anyarray`.
    - Добавляемый массив непустой;
    - Тип элементов добавляемого должен совпадать с типом элементов исходного массива;
    - Если исходный массив непустой: `arg_ndim = elem_ndim + 1`, размерности и lower bounds оставшихся измерений исходного массива и измерений добавляемого массива должны совпадать;
    - Для непустого исходного массива `|size| >= arg_dims[0]`;
    - `size = 0`: для пустого исходного массива — пустой массив; для непустого — ошибка;
    - Выход: массив размерности `elem_ndim + 1`; `res_dims[0] = |size|`; `res_lbs[0]` равен lower bound исходного массива для непустого входа, иначе 1; остальные размерности/lower bounds берутся из добавляемого массива;
    - NULL-элементы исходного массива и добавляемого массива сохраняются.
- **Алгоритм:** `deconstruct_array` для обоих массивов => проверки формы/типа => `memcpy` блоков добавляемого массива и исходного массива в нужном порядке => `construct_md_array`.
- **Ограничения:** 
    - Добавляемый массив непустой; 
    - Тип элементов добавляемого должен совпадать с типом элементов исходного массива;
    - Для непустого исходного массива обязательна согласованность размерностей и lower bounds; при пустом исходном массиве его форма игнорируется, результат строится от добавляемого массива;
    - Для непустого исходного массива `arg_ndim = elem_ndim + 1`;
    - Для непустого исходного массива `size != 0`.

#### **6. array_slice**

- **Назначение:** Нахождение среза массива по первому измерению с указанным шагом.
- **Прототип:** `array_slice ( anyarray, start integer, end integer, step integer DEFAULT 1 ) → anyarray`
- **Сигнатура (SQL):** `FUNCTION array_slice(anyarray, start integer, end integer, step integer DEFAULT 1) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Вход/выход:**
    - Вход: непустой `anyarray`, `start integer`, `end integer`, `step integer`;
    - `start`/`end` — 1-based (индексация с единицы); положительные индексы считаются с начала, отрицательные — с конца (`-1` — последний элемент);
    - После нормализации `start`/`end` становятся 0-based;
    - `step` должен быть `> 0`;
    - Выход: массив той же размерности; срез выполняется по первому измерению;
    - `res_dims[0] = floor((end - start) / step) + 1`; `res_lbs[0] = 1`; остальные размерности и lower bounds копируются из входа;
    - NULL-элементы сохраняются.
- **Используемый алгоритм/решение:**
    `deconstruct_array` => вычисление `element_size = произведение dims[1..]` => копирование блоков элементов/Null-карты с шагом `step * element_size` => `construct_md_array`.
- **Ограничения:**
    - Исходный массив непустой;
    - `step > 0`;
    - `start <= end`;
    - Входные индексы строго 1-based (индекс 0 - ошибка).
- **Предполагаемые тесты:** (SZ — размер первого измерения)
    - Обычный случай — несколько тестов:
        - Разные типы элементов массива;
        - `2 <= start < end <= SZ` (с учётом ограничения на `start`);
        - `-SZ < start < end <= -1`;
        - `0 < step < SZ - 1`;
    - Пустой массив — ошибка;
    - Большой массив;
    - N-мерный массив — штатно, срез по первому измерению;
    - Массив с NULL-элементами — штатно;
    - `start == end` — штатно, результат из одного элемента (при допустимом `start`);
    - `step >= SZ` — штатно, результат из одного элемента (при допустимом `start`);
    - Ошибка ввода:
        - 1 аргумент — не массив;
        - `start` — не int;
        - `end` — не int;
        - `start > end`;
        - `step <= 0`.

#### **7. array_repeat**

*Примечание: реализованы две C-функции, регистрируемые под одним SQL-именем `array_repeat` для перегрузки.*

- **Назначение:** Создание массива из заданного элемента или массива, повторённого `count` раз.
- **Прототипы:**
    1. `array_repeat ( anyelement, count integer ) → anyarray`
    2. `array_repeat_arr ( anyarray, count integer ) → anyarray`
- **Сигнатуры (SQL):**
    1. `FUNCTION array_repeat(anyelement, count integer) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
    2. `FUNCTION array_repeat(anyarray, count integer) RETURNS anyarray LANGUAGE C IMMUTABLE STRICT`
- **Предполагаемые тесты:**
    - Обычный случай — несколько тестов:
        - Разные типы элементов массива;
        - `count > 0`;
    - 1 аргумент — N-мерный массив — штатно, результат — (N+1)-мерный массив;
    - `count == 0` — пустой массив;
    - Пустой входной массив для `array_repeat_arr` — пустой массив;
    - Большое значение `count`;
    - Ошибка ввода (`count < 0`).

##### 7.1. `array_repeat(anyelement, integer)`

- **Вход/выход:**
    - Вход: `anyelement`, `count integer`;
    - `0 =< count =< MaxAllocSize / sizeof(Datum)`;
    - Выход: одномерный массив длины `count`, `lbs = 1`, все элементы — заданное значение;
    - `count = 0` — пустой массив.
- **Алгоритм:** заполнение `Datum* res_elems` значением аргумента => `construct_array`.
- **Ограничения:** 
    - `count` неотрицателен; 
    - `value` - не NULL (функция STRICT).

##### 7.2. `array_repeat_arr(anyarray, integer)`

- **Вход/выход:**
    - Вход: `anyarray`, `count integer`;
    - `0 =< count =< MaxAllocSize / sizeof(Datum) / N`, где N - размер входного массива;
    - Выход — массив размерности `arg_ndim + 1`: `res_dims[0] = count`, `res_lbs[0] = 1`; остальные размерности и lower bounds копируются из входа;
    - Если `count = 0` или входной массив пуст — возвращается пустой массив;
    - NULL-элементы входного массива сохраняются.
- **Алгоритм:** `deconstruct_array` => `memcpy` блоков элементов/Null-карты `count` раз => `construct_md_array`.
- **Ограничения:** 
    - `count` неотрицателен; 
    - При пустом входном массиве результат пустой независимо от `count`.


### Дополнительные функции

В этом разделе приведены функции, не требуемые в изначальном ТЗ, но нужные для реализации вышеописанных:

- `pgau_is_numeric_type(eltp)` — true для `INT2/INT4/INT8`, `FLOAT4/FLOAT8`, `NUMERIC`, `OID`, `MONEY`.
- `pgau_is_text_type(eltp)` — true для `TEXT`, `VARCHAR`, `BPCHAR`, `CHAR`, `NAME`, `BYTEA`.
- `pgau_array_is_empty(ndim, dims)` — true, если число измерений или число элементов равно 0.
- `appendStringInfoNChars(str, c, n)` — добавляет `n` символов `c` в `StringInfo`.
- `pgau_numeric_is_zero(eltp, a)` — сравнение числового Datum с нулём; для неподдерживаемого типа — ошибка.
- `pgau_text_is_empty(eltp, a)` — проверка текстового/бинарного Datum на пустоту; для неподдерживаемого типа — ошибка.
- `pgau_datum_to_json_cstring(value, type)` — преобразует Datum в C-строку JSON: числовые/boolean — без изменений, остальные — с `escape_json`.
- `pgau_array_to_StringInfo(dest, elems, nulls, eltp, nelems, ndim, dims)` — сериализует массив в JSON-подобную строку.
