## Дизайн-документ: расширение pg_array_utils

-------
#### *Примечание: в данный момент документ находится на стадии черновика и будет многократно изменяться и дополняться*
-------

### Цель: 
Разработать расширение `pg_array_utils` для PostgreSQL на языке C с набором IMMUTABLE функций, реализующих преобразование и манипуляции с одномерными и двумерными массивами.

### Общие решения:
- Определение всех функций STRICT
- Использование для тестирования регрессионные и TAP- тесты.

### Разрабатываемые функции:

#### **1. array_flatten**

- **Назначение:** Преобразование многомерного массива в одномерный (в порядке хранения по строкам).
- **Прототип:** `array_flatten ( anyarray ) → anyarray`
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    Использовать `deconstruct_array` ко входному массиву и собрать с помощью `construct_array` новый с размерностью 1, простой по написанию и достаточно эффективный вариант.
    Альтернатива: пересчитать для результирующего массива размер заголовка и сдвиг (`dataoffset`) и скопировать данные и NULL-карту с помощью `memcpy`. Это несколько быстрее, однако этот способ может не сработать на других версиях PostgreSQL, и выигрыш в скорости не окупает сложность написания.
- **Предполагаемые тесты:**
    - Обычный случай - несколько тестов (разные типы элементов массива);
    - Одномерный массив - возврат ввода;
    - Пустой массив - возврат ввода;
    - Большой массив;
    - N-мерный массив - штатно;
    - Ошибка ввода (аргумент - не массив).

#### **2. array_chunk**

- **Назначение:** Разбиение одномерного массива на массив массивов (чанков) заданного размера. Последний чанк может быть короче.
- **Прототип:** array_chunk ( anyarray, size integer ) → anyarray 
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    Аналогично array_flatten использовать `deconstruct_array` и `construct_md_array` для сборки двумерного массива с нужными размерностями.
- **Предполагаемые тесты:**
    - Обычный случай - несколько тестов:
        - Разные типы элементов массива;
        - Разные значения size;
    - N-мерный массив - ошибка; *(Примечание: возможны изменения в дальнейшем)*
    - Пустой массив - ошибка;
    - Большой массив;
    - Ошибка ввода:
        - 1 аргумент - не массив;
        - size - не int;
        - size <= 0;
        - size > длины массива;
    - Массив с NULL элементами - штатно.

#### **3. array_zip**

- **Назначение:** Формирование массива json, каждый из которых представляет собой кортеж, содержащий по одному элементу из каждого массива. Длина результата равна длине самого длинного массива; недостающие элементы заменяются на NULL.
- **Прототип:** `array_zip ( anyarray, anyarray \[, ...\] ) → anyarray`
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    Получить количество входных массивов с помощью `PG_NARGS()`; создать буферы для хранения всех входных массивов и их данных и буфер `Datum*` для хранения результирующих кортежей; к каждому входному массиву применить `deconstruct_array` и записать результаты в соответствующие буферы; получить максимальную длину массива `max_len`; Цикл по `i=\[0 .. max_len\]`: с помощью `StringInfoData jsonbuf` сформировать i-ю строку и использовать `DirectFunctionCall1(jsonb_in, CStringGetDatum(jsonbuf.data));`. *(Примечание: возможны изменения в дальнейшем)*
- **Предполагаемые тесты:**
    - Обычный случай - несколько тестов (разное количество входных массивов);
    - Большое количество массивов;
    - Большие размеры массивов;
    - Ошибка ввода (ни одного входного массива);
    - Один или несколько массивов пустые - штатно;
    - Один или несколько массивов состоят из NULL - штатно;
    - Один или несколько N-мерных массивов - штатно.

#### **4. array_compact**

- **Назначение:** Удаление "пустых" элементов. Режимы:
                    - 'null' – удалить NULL;
                    - 'zero' – удалить числовые нули;
                    - 'empty' – удалить пустые строки;
                    - 'falsy' – удалить NULL, false, 0, ''.
- **Прототип:** `array_compact ( anyarray, mode text DEFAULT 'null' ) → anyarray` 
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    Использование `deconstruct_array` => получение `elements[]`, `nulls[]` и `nelems`. Далее создание `Datum* new_elems` и проход по `elements` - i-й элемент добавляется в `new_elems`, если (зависит от режима работы):
        1. 'null' - `!nulls[i]`;
        2. 'empty' и 'zero' - `elements[i] != ''` и `elements[i] != 0` соответственно;
        3. 'falsy' - случай 1 && случай 2 && `elements[i] != false`. 
    После фильтрации элементов вызов `construct_array`.
- **Предполагаемые тесты:**
    - Обычный случай - несколько тестов:
        - Массив строк + 'empty';
        - Массив чисел + 'zero';
        - Массив строк + 'null' и 'falsy';
        - Массив чисел + 'null' и 'falsy';
        - Массив boolean + 'falsy';
    - N-мерный массив - штатно, удаление элементов с последующей перепаковкой;
    - Несоответствие режима работы входному массиву - ошибка:
        - 'zero' не для массива чисел;
        - 'empty' не для массива строк;
        - 'falsy' не для массива boolean;
    - Пустой массив - возврат ввода;
    - Массив с NULL элементами - штатно;
    - Большой массив;
    - Ошибка ввода:
        - 1 аргумент - не массив;
        - mode - не строка;
        - mode - не существующий режим.

#### **5. array_pad**

*Примечание: планируется реализация второй функции для корректной обработки случая, когда value - anyarray. Обе функции будут зарегистрированы под одним именем в SQL.*

- **Назначение:** Дополнение массива до указанной длины элементами value, добавляя их в конец (value может быть N-мерным массивом). Если size отрицательный – дополняет в начало.
- **Прототипы:** 
    1. `array_pad ( anyarray, size integer, value anyelement ) → anyarray`
    2. `array_pad_arr ( anyarray, size integer, value anyarray ) → anyarray`
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    1. Использование `deconstruct_array` и получение `elements[]`. Создание `Datum* res_elems` размера `size` и заполнение его части `value` с помощью `for`. Далее использование `memcpy` для заполнения оставшейся части содержимым `elements[]`. Использование `memcpy` обусловлено большей скоростью, чем при использовании `for` в этом случае.
    2. Использование `deconstruct_array` для первого и третьего аргументов, получение их данных; расчет требуемого размера `Datum* res_elems` и `nulls` и расчет новых `dims` и `lbs`; использование `memcpy` для копирования содержимого массива `value` в нужные места; копирование содержимого исходного массива.
- **Предполагаемые тесты:**
    - Обычный случай - несколько тестов:
        - Разные типы элементов массива;
        - Разные значения size;
        - size == длине массива;
    - Пустой массив - штатно;
    - Ошибка ввода:
        - 1 аргумент - не массив;
        - size - не int;
        - \|size\| < длины массива;
        - \|size\| > MAX_INT;
        - тип value не соответствует типу массива;
    - Большой массив;
    - N-мерный массив - штатно, тип value - (N-1)-мерный массив (используется `array_pad_arr`);
    - Массив с NULL элементами - штатно.

#### **6. array_slice**

- **Назначение:** Нахождение заданного среза массива по указанным индексам с указанным шагом
- **Прототип:** `array_slice ( anyarray, start integer, end integer, step integer DEFAULT 1 ) → anyarray`
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    Использование `deconstruct_array` и получение `elements[]`, вычисление размера результирующего массива и его создание, поэлементное копирование нужного числа элементов с помощью `for`, далее `construct_array`. Здесь используется `for`, т.к. учитывая шаг, элементы могут лежать не непрерывно. *Примечание: на рассмотрении использование memcpy для копирования отдельных элементов, это должно дать ускорение, если элемент массива - массив.*
- **Предполагаемые тесты:** (далее SZ - размер массива)
    - Обычный случай - несколько тестов:
        - Разные типы элементов массива;
        - 1 <= start < end <= SZ;
        - -SZ <= start < end <= -1;
        - 0 < step < SZ - 1;
    - Пустой массив - ошибка;
    - Большой массив;
    - N-мерный массив - штатно, тип элемента - (N-1)-мерный массив;
    - Массив с NULL элементами - штатно;
    - start == end - штатно, результат - массив с единственным элементом;
    - step == SZ - штатно, результат - массив с единственным элементом;
    - Ошибка ввода:
        - 1 аргумент - не массив;
        - start - не int;
        - end - не int;
        - start > end;
        - step <= 0.
    
#### **7. array_repeat**

*Примечание: планируется реализация второй функции для корректной обработки случая, когда первый аргумент - anyarray. Обе функции будут зарегистрированы под одним именем в SQL.*

- **Назначение:** Создание массива из заданного элемента (элемент может быть N-мерным массивом). Возвращает массив, состоящий из count экземпляров заданного элемента.
- **Прототипы:** 
    1. `array_repeat ( anyelement, count integer ) → anyarray`
    2. `array_repeat_arr ( anyarray, count integer ) → anyarray`
- **Сигнатура (SQL):** *здесь в дальнейшем появится сигнатура функции*
- **Используемый алгоритм/решение:**
    1. Создание `Datum* res_elems` размера `sizeof(Datum) * count`, далее цикл на `count` итераций и использование `datumCopy` для заполнения `res_elems` копиями первого аргумента и использование `construct_array`.
    2. Использование `deconstruct_array` для получения данных N-мерного массива из первого аргумента, создание новой формы для (N+1)-мерного массива (расчет новых `dims` и `lbs`), далее аналогичное поэлементное заполнение (N+1)-мерного массива с последующим вызовом `construct_md_array`. Альтернатива: использовать функцию `memcpy` для копирования `elements` и `nulls` входного массива `count` раз. Несмотря на возможное ускорение, этот способ не был использован ввиду возможного изменения структуры загловка типа `varlena`, и, соответственно, потери работоспособности функции в таком случае.
- **Предполагаемые тесты:**
    - Обычный случай - несколько тестов:
        - Разные типы элементов массива;
        - count > 0;
    - 1 аргумент - N-мерный массив - штатно, результат - (N+1)-мерный массив;
    - count == 0 - штатно, результат - пустой массив;
    - Большое значение count;
    - Ошибка ввода (count < 0).
